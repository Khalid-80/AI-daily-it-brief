# AI Daily IT Intelligence Brief — نسخة مجانية / بدون بنية تحتية خاصة

تنفيذ لنفس فكرة العرض التقديمي الأصلي (RSS → تحليل AI → نشرة معتمدة في Teams)
باستخدام أدوات مجانية فقط: **GitHub Actions** للتشغيل والجدولة،
**Groq** لاستضافة نموذج مفتوح المصدر (Llama)، و**Teams Workflows webhook**
للنشر. لا تحتاج جهازك ولا أي سيرفر تديره أنت.

استشاري بالكامل: لا يعدّل أي إعداد ولا ينفذ أي إجراء تلقائي على أي نظام —
فقط يقرأ RSS عام وينشر ملخصًا نصيًا بعد موافقة بشرية.

---

## 1. أنشئ مستودع GitHub

- أنشئ **مستودعًا عامًا (Public)** — هذا مهم: بوابة الموافقة البشرية
  (Required Reviewers) مجانية فقط على المستودعات العامة في الخطة المجانية.
  لا يوجد في هذا المستودع أي سر أو بيانات حساسة (المفاتيح تُخزَّن كـ Secrets
  منفصلة عن الكود)، فكونه عامًا لا يشكّل خطرًا.
- ارفع محتوى هذا المجلد كما هو.

## 2. أنشئ مفتاح Groq مجاني

1. سجّل في https://console.groq.com (مجاني، بدون بطاقة ائتمان).
2. أنشئ API Key من قسم API Keys.
3. في مستودع GitHub: **Settings → Secrets and variables → Actions → New
   repository secret** باسم `GROQ_API_KEY` وقيمته المفتاح.

النموذج الافتراضي في الكود هو `llama-3.1-8b-instant` (مفتوح المصدر،
مستضاف مجانًا عبر Groq). تقدر تغيّره بمتغيّر `GROQ_MODEL` إذا احتجت.

## 3. أنشئ Webhook في قناة Teams (الطريقة الحديثة)

⚠️ ملاحظة مهمة: الـ Incoming Webhook القديم (Office 365 Connector) توقف
نهائيًا في مايو 2026. الطريقة الحالية هي عبر تطبيق **Workflows**:

1. في القناة المطلوبة داخل Teams: **⋯ (خيارات إضافية) → Workflows**.
2. ابحث عن قالب باسم قريب من: **"Post to a channel when a webhook
   request is received"**.
3. أكمل المعالج واختر القناة، ثم انسخ رابط الـ Webhook الناتج.
4. في GitHub: أضف Secret باسم `TEAMS_WEBHOOK_URL` وقيمته هذا الرابط.
5. **تحقق من اسم الحقل** الذي يتوقعه القالب (غالبًا `text`). إن كان مختلفًا،
   عدّل `TEXT_FIELD_NAME` في `scripts/publish_to_teams.py`.

## 4. أنشئ بوابة الموافقة البشرية (Human Review Gate)

هذا يطبّق بند "مراجعة بشرية قبل النشر" من التصميم الأصلي، مجانًا بالكامل:

1. **Settings → Environments → New environment** باسم `teams-publish`.
2. فعّل **Required reviewers** وأضف نفسك أو المراجع المسؤول من IT.
3. من الآن، أي تشغيل يومي يتوقف عند وظيفة `publish` وينتظر ضغطة "Approve"
   قبل ما يُنشر أي شيء في Teams.

## 5. اضبط قائمة المصادر (RSS)

عدّل `config/feeds.json`:
- استبدل أي رابط يحتوي `REPLACE_WITH_...` برابط RSS حقيقي (Microsoft
  Message Center، Windows Release Health، نشرات البائعين المعتمدين... إلخ).
- `lookback_hours`: مدة النافذة الزمنية للأخبار "الحديثة".
- `max_items`: أقصى عدد أخبار تُرسل للتحليل يوميًا (يبقيك ضمن الحصة المجانية).

## 6. جرّب تشغيلًا يدويًا أولًا

في تبويب **Actions** بالمستودع → اختر الـ workflow → **Run workflow**
(هذا مفعّل عبر `workflow_dispatch` في ملف الـ workflow). راجع نتيجة
`brief.md` كملف مرفق (artifact) قبل ما توافق على أول نشر فعلي.

## التكاليف والحدود (Costs & limits)

| العنصر | الحد المجاني | ملاحظة |
|---|---|---|
| GitHub Actions | دقائق مجانية شهريًا (غير محدودة عمليًا للمستودعات العامة) | تشغيل يومي بهذا الحجم يستهلك دقائق قليلة فقط |
| Groq API | حصة طلبات يومية مجانية | كافية لعدد أخبار محدود يوميًا؛ راقب لوحة التحكم دوريًا |
| Teams Workflows webhook | مجاني بالكامل لهذا الاستخدام | لا يحتاج Power Automate Premium |

## نقاط يجب تذكرها لاحقًا (من نقاش المخاطر)

- راقب لوحة Groq بين فترة وأخرى — السياسات المجانية قد تتغيّر.
- أضف تنبيهًا (مثلًا عبر إشعارات فشل GitHub Actions الافتراضية على
  بريدك) حتى تعرف فورًا لو فشل التشغيل اليومي.
- وثّق من يملك حساب GitHub ومفتاح Groq رسميًا، حتى لا يتحول المشروع
  إلى "Shadow IT" بلا مالك واضح.
